너는 「AI 인수인계」 기능 개발자다. 대상 부서는 민원여권과, 노인장애인과, 동 행정복지센터 세 곳뿐이다.

## 기능
1. **업무 카드**: 방(부서)에 들어가면 업무ID별 카드(업무명, 한 줄 설명, 근거, 연간 시기, 관련 도구 수).
2. **연간 달력**: "11월에 뭐 해야 해요?" → 월별 할 일. `tasks.json`의 `schedule` 필드에서 만들고, 없으면 "자료 필요"로 표시(AI가 지어내지 않음).
3. **단계 체크리스트**: 업무 하나를 고르면 처리 단계, 필요 서류, 유의사항. 각 항목에 rule_id를 붙이고 `lib/evidence/verify.ts` 통과분만 조문 링크.
4. **후임자 질의응답**: 지식 베이스 안에서만 답하는 대화. 답할 근거가 없으면 "인수인계 자료에 없습니다. 전임자·팀장 확인 필요"라고 답하고 질문을 `data/kb/open_questions.json`에 남김.
5. **축적 루프**: 열린 질문에 사람이 답을 달면(승인 버튼) 지식 베이스에 FAQ로 추가 → 다음 후임자부터 바로 답함. 화면에 "이 방이 배운 것 N건" 카운터.

## 원칙
- 주무관 정보는 `data/kb/officers.json` (부서당 1명, 이름·말투만. 제안서처럼 화면에도 '몇 명'을 강조하지 않음).
- 프롬프트는 `lib/ai/prompts/officer/*.md`. 지식 베이스 발췌를 `<kb>` 태그로, 사용자 질문을 `<user_data>` 태그로 감싼다.
- 개인정보가 얽힌 업무(장애인 등록, 기초연금 등)는 절차·기준만 다루고 개인 사례는 가상으로만.
- 모든 출력 상단에 "AI 초안 · 최종 판단은 담당자".

## 완료 기준
- 세 부서 각각 업무 카드 10개 이상, 달력·체크리스트·질의응답 동작
- 근거 없는 질문에 "자료에 없음"으로 답하는 테스트 통과
- 열린 질문 → 승인 → 다음 질문에서 답하는 흐름 E2E 통과
