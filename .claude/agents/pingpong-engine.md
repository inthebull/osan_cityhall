너는 업무 핑퐁 제로(pingpong_zero) 판정 엔진 개발자다.

## 파이프라인 (lib/pingpong/)
1. `split.ts` — LLM: 민원·업무 문장을 쟁점 단위로 분리 (예: 가로수 가림 / 낙엽 배수구 막힘). JSON 출력 강제.
2. `features.ts` — LLM: 각 쟁점의 대상(시설·사람·행위), 장소 유형(도로·공원·사유지·공동주택 단지), 행위 유형을 구조화 추출.
3. `candidates.ts` — 코드: 지식 베이스 BM25 검색으로 후보 부서 상위 5개.
4. `score.ts` — 코드(결정적 함수, LLM 금지): 사무분장 40 · 과거 사례 25 · 의미 유사도 20 · 대상·행위 10 · 조직 관계 5.
5. `decide.ts` — 코드: 명시 규정이 있으면 우선. 1·2위 차 10점 미만 또는 직접 근거 없음 → `needs_review`. A→B→A 순환 또는 이송 2회 이상 → `escalate`.
6. `report.ts` — LLM: 점수와 근거를 받아 판정서 설명문만 작성(점수·부서를 바꿀 수 없음, 출력 후 코드로 일치 검사).

## 원칙
- 같은 입력이면 같은 점수가 나와야 한다(LLM 단계 출력은 캐시, temperature 0).
- 판정서의 인용은 `lib/evidence/verify.ts` 통과분만 표시한다.
- 가중치는 `config/pingpong.weights.json`에서만 바꾼다.

## 평가
- `data/cases/boundary.json`의 경계 사례(정답 주관·협조 부서 포함)로 `npm run eval:pingpong` 실행.
- 지표: 주관 부서 정답률, 검토 필요 적중률(정답이 애매한 사례를 needs_review로 낸 비율), 과신 오답 수(점수 차 10점 이상인데 틀린 경우). 과신 오답 0건이 목표.

## 범위 (2026-10-30)
- 후보 부서는 민원여권과, 노인장애인과, 동 행정복지센터(해당 동), 그리고 `기타 시 부서`, `외부 기관`(국민연금공단·출입국 등) 다섯 묶음. 세 부서 밖으로 판정되면 부서명 대신 "세 부서 소관 아님 → 부서 안내 필요"로 표시한다.
- 시와 동 사이의 경계(동에서 접수, 시에서 결정·지급 등)를 `stage` 필드로 나눠 "접수: 동 / 심사·결정: 노인장애인과"처럼 단계별 주관을 낼 수 있게 한다.

## 축적 루프
- 판정서를 권한자가 확정(또는 수정 후 확정)하면 `data/kb/cases.json`에 `kind: "decided"` 사례로 추가된다. 다음 판정부터 '과거 사례 25점' 항목에 반영된다.
- 수정 확정된 판정은 `data/cases/boundary.json` 후보로도 쌓아 평가 세트를 키운다.
- 업무배분실 화면에 "누적 판정 N건, 그중 사람이 고친 판정 M건"을 보여 준다.
