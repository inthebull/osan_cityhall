# 오산시 슬라이드 디자인 레퍼런스

PPT를 만들거나 고치기 전에 이 스킬을 읽고, 장마다 어떤 패턴(P번호)을 쓰는지 정한 뒤 `osan-pptx-design` 순서대로 만든다.
색·서체·상징 규칙은 루트 `DESIGN.md`가 우선이다. 이 스킬은 "어떻게 하면 더 잘 보이는가"를 레퍼런스로 뒷받침한다.

## 쓰는 순서

1. **[references/patterns.md](references/patterns.md)** 에서 장 종류에 맞는 패턴을 고른다. 각 패턴에 오산시용 값(좌표·크기·색)과 출처가 있다.
2. 장 목록을 만들고 장마다 패턴 번호를 붙인다. 예: 표지 P12, 요약 P09, 업무 P02+P03+P14, 첫 주 P08, 협업 P06, 장 구분 P07.
3. 같은 배치가 3장 넘게 이어지면 P07(장 구분)이나 P09(요약)로 리듬을 바꾼다.
4. `npm run render:handover`로 그려 보고, 아래 **점검표**로 장마다 확인한다.
5. 새 레퍼런스를 찾으면 [references/sources.md](references/sources.md)에 출처와 접속 결과를 적고, 패턴은 `patterns.md`에 번호를 이어 붙인다.

## 핵심 원칙 (레퍼런스가 공통으로 말하는 것)

- **결론 먼저.** 제목이나 헤드메시지 한 줄로 3초 안에 요점이 보여야 한다(Duarte Glance Test, 컨설팅식 action title, 1매 보고서의 취지 상자).
- **틀은 고정, 내용만 바뀐다.** 제목·본문·바닥의 자리가 모든 장에서 같다(ONS, 인도 정부 지침, GDS).
- **색은 60·30·10.** 흰색·회색 60, 남색 30, 청록 10. 상태 색(검토·확인 필요)은 5% 이하, 반드시 글자 라벨과 함께(KRDS).
- **상자보다 여백과 가는 선.** 묶음은 간격으로 보여 주고, 구분은 0.75pt 선으로(Presentation Zen, 스위스 격자). 그림자·그라데이션·애니메이션 금지.
- **글자 단계는 적게, 굵기는 두 가지.** 보통·굵게만. 본문은 왼쪽 정렬, 본문 14pt 이상(GOV.UK, KRDS, 컨설팅 기준).
- **공문서 관례.** 항목 기호 1. → 가. → 1) → 가), 날짜 `2026. 10. 30.`, 쪽 번호는 아래 가운데.
- **읽는 자료(slidedoc).** 인수인계 덱은 발표보다 읽히는 자료다. 조금 더 촘촘해도 되지만 훑어 읽히게 위계를 분명히 한다(Duarte Slidedocs).

## 점검표 (장마다)

- [ ] 제목이 한 줄이고, 헤드메시지(있으면)가 한 줄로 요점을 말하는가 (P02, P03)
- [ ] 제목·배지·바닥 위치가 다른 장과 같은가 (P01)
- [ ] 남색·청록 외 색이 상태 표시에만 쓰였고 라벨이 붙었는가 (P13)
- [ ] 상자가 꼭 필요한 곳(헤드메시지, 근거, 상태)에만 있는가 (P05)
- [ ] 본문 14pt 이상, 각주 10pt, 글자 넘침·겹침 없는가 (P11)
- [ ] 쪽 번호가 아래 가운데, 근거 각주가 본문과 겹치지 않는가 (P10)
- [ ] 표에 세로선이 없고 머리 아래 남색 선이 있는가 (P06)
- [ ] 같은 배치가 3장 넘게 이어지지 않는가 (P07)

## 접속 한계

이 작업 환경에서는 Canva·Behance·Dribbble·미리캔버스·망고보드·Figma 같은 이미지 중심 갤러리가 막혀 있어 글로만 확인했다(sources.md에 기록).
화면을 직접 보고 고르고 싶으면 사람이 PC 브라우저로 열어 캡처를 주거나, PC 연결로 브라우저를 보게 하면 이 목록에 추가한다.
