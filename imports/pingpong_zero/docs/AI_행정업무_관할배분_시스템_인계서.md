# AI 행정업무 관할·배분 지원시스템 — 아이디어 인계서

> 목적: 이전 대화를 모르는 AI가 기획·설계·프로토타입 개발을 이어갈 수 있도록 작성한 문서.
> 상태: 아이디어 단계. 아래 가중치·점수·기준·시연 사례는 설계 제안 또는 가상 예시이며, 실제 지자체 규정이나 검증된 성능이 아니다.

## 1. 프로젝트 요약과 배경

민원·제안·시장 및 간부 지시·공약·내부 업무를 입력하면, 조직 규정과 사무분장 및 처리 이력을 검색하여 **가장 적합한 주관부서·팀·담당업무와 협조부서를 근거 및 점수와 함께 추천**하는 시스템이다. 담당자 정보가 최신이고 접근 권한이 있는 경우 개인 담당자까지 연결한다.

사용자의 원래 구상은 애매한 업무의 담당을 명확히 정해 부서 간 갈등과 억울한 업무 전가를 막는 것이다. 구현 방향은 **AI의 근거 기반 배정 권고 → 권한 있는 사람의 확정 → 이의제기·조정 이력 관리**로 제안한다. AI에 최종 배정 권한을 부여할지는 별도 조직 의사결정 사항이다.

시정연구모임의 프로토타입 후보로, 간부·실무자·시민이 효용을 바로 이해하고 발표에서 효과를 보여줄 수 있어야 한다. 기존 대화에서는 10~11월 개발·12월 발표를 염두에 두었으나 실제 일정은 재확인한다. 특정 시장 관심사와의 직접 연결보다 실현가능성·완성도·시정 기여·확산성을 중시한다. 오산시가 대화에 언급됐지만 적용 지자체와 조직 범위는 아직 확정하지 않는다.

## 2. 문제 정의와 목표

- 복합적이거나 새로운 업무는 사무분장 경계가 불명확해 여러 부서를 오간다.
- 시민은 담당부서를 찾다가 반복 설명·이송·처리 지연을 겪는다.
- 직원은 관할 확인과 부서 간 협의에 시간을 쓰며, 부서장의 영향력이나 관행에 따라 업무가 불공정하게 전가될 수 있다.
- 과거 배정 이유와 조정 결과가 축적되지 않아 같은 갈등이 반복된다.

목표는 최초 배정의 적합성을 높이고, 불필요한 재이송·협의시간·갈등을 줄이며, 누구나 확인할 수 있는 동일한 근거로 배정하는 것이다. 업무 관할 판단과 업무량·인력배분 판단은 구분한다. 인력이 부족하다는 이유만으로 관할을 바꾸지 않는다.

| 제안 담당자 / 시민·직원 제안 | 실행 대상과 행정행위를 분석해 검토 주관과 협조부서 연결 |

| 각 부서 직원 / 내부 과제·공문·신규 업무 | 소관 확인, 유사사례 조회, 재배정 근거 제출 |

| 시민 / 향후 외부 서비스 | 일상언어로 문의하고 담당 창구·접수 경로 안내받기 |

## 4. 핵심 기능과 결과 화면

1. **업무 분석:** 입력에서 요구사항·대상 시설·위치·관리주체·행정행위·핵심 및 부수 쟁점을 추출한다. 판단에 필요한 정보가 빠지면 추가 질문한다.
2. **후보 검색:** 조직·사무분장·매뉴얼·처리사례에서 후보 부서·팀·업무를 찾는다.
3. **배정 권고:** 상위 후보, 업무적합도, 주관·협조 역할, 후보 간 차이와 제외 이유를 제시한다.
4. **근거 열람:** 원문 인용, 문서명·조항·쪽·버전·시행일·원문 위치를 표시한다. 검색되지 않은 근거는 생성하지 않는다.
5. **확정·재검토:** 권한자가 수용·수정·보류하고 사유를 기록한다. 담당자 부재·겸임·미지정은 팀 단위로 안내한다.
6. **이력·통계:** 최초 권고부터 최종 확정까지 추적하고 재이송률·조정시간·반복 경합 업무를 집계한다.

권장 출력 필드: `사건ID / 입력유형 / 쟁점목록 / 추가확인사항 / 주관부서·팀·담당업무 / 협조부서별 역할 / 후보별 점수·항목별 내역 / 근거목록 / 유사사례 통계 / 근거충분도 / 검토상태 / 데이터기준일 / 재배정이력`.

## 5. 신뢰·설명가능성 장치

- **규정 근거:** 어떤 업무분장 문구가 어떤 쟁점과 연결되는지 보여준다. 문서 간 충돌은 숨기지 않고 현행성·효력·적용범위를 확인하도록 표시한다.
- **유사사례 통계:** 검색된 비교 가능 사례의 기간·조건·건수·최종 처리부서·표본 수를 함께 표시한다. 예: “유사사례 43건 중 최종 처리 38건(88.4%)”은 가상 예시다. 최초 배부만 된 건과 처리가 확정된 건을 구분한다.
- **업무적합도:** 후보별 0~100점과 산식을 공개한다. 후보 점수 합계는 100일 필요가 없으며, 정답 확률이나 업무 부담 비율이 아니다.
- **근거충분도:** 자료 최신성·직접 근거 유무·자료 충돌·필수정보 누락을 별도 표시한다. 초기에는 높음/중간/낮음으로 제시한다.
- **판정 신뢰도:** LLM이 스스로 말한 확신을 정확도처럼 표시하지 않는다. 향후 독립 검증자료로 보정한 경우에만 의미·표본·오차와 함께 확률을 제공한다.
- **경합 비교:** 1·2순위의 적용 근거와 반대 근거를 나란히 보여주고, 판단을 바꿀 추가 정보도 설명한다.

## 6. 점수 산정 로직 초안

현재 유효한 명시적 소관·제외 규정과 시설 관리주체 등을 먼저 확인한다. 명시적 규정에 어긋나는 후보를 과거 관행이나 의미 유사도로 상위 추천하지 않는다. 문서 충돌·소관 공백은 조정 대상으로 보낸다.

각 항목을 0~100으로 평가한 뒤 다음 가중합을 출발점으로 사용한다.

`업무적합도 = 0.40×사무분장 근거 + 0.25×과거 확정사례 + 0.20×의미 유사도 + 0.10×대상·행위·키워드 일치 + 0.05×조직·협업 관계`

| 항목 | 산정 방향 |
|---|---|
| 사무분장 근거 40% | 해당 업무가 현행 분장에 직접 명시됐는지, 적용 대상·행위가 일치하는지 |
| 과거 확정사례 25% | 조건이 유사하고 최종 배정이 확인된 사례의 분포·최근성·표본 규모 |
| 의미 유사도 20% | 입력 쟁점과 담당업무 설명의 의미상 관련성 |
| 대상·행위·키워드 10% | 시설 유형·관리주체·행정행위 등 핵심 요소 일치 |
| 조직·협업 관계 5% | 총괄 기능과 명시된 주관·협조 관계의 일치 |

항목별 산정 기준을 고정하고 계산은 코드로 수행한다. LLM이 최종 점수를 임의 생성하지 않게 한다. 근거 중복이 점수를 부풀리지 않도록 중복 문서를 제거한다. 자료가 없는 항목은 결측으로 표시하고, 재가중 여부와 데이터 충족률을 공개한다. 결측을 부적합으로 단정하지 않는다.

운영 기준 예시: 상위 점수 차이가 10점 미만이거나 직접 근거가 없으면 검토 필요, 소관 규정이 충돌하면 조정 필요로 표시한다. 이 기준과 가중치는 전문가가 판정한 별도 평가사례로 조정한다. 복합 업무는 쟁점별로 점수를 계산한 뒤 주관·협조 관계를 정한다.

## 7. 데이터와 지식베이스

| 데이터 | 용도·관리 사항 |
|---|---|
| 행정기구 관련 조례·규칙 등 조직 규정 | 조직 기능·소관의 공식 근거; 현행 여부·시행일 관리 |
| 부서별 사무분장 | 업무 관할 판단의 핵심; 업무ID·부서ID 연결 |
| 팀별·개인별 업무분장 | 실제 처리 단위 연결; 발령·전보·겸임·공석 반영 |
| 업무편람·매뉴얼·협의 절차 | 처리 단계와 주관·협조 관계 보완 |
| 과거 민원 배부·처리 이력 | 최초·중간·최종 배정, 재이송 사유, 처리 결과 구분 |
| 과거 공문 배부·처리 이력 | 내부 업무·복합 과제 유사사례 검색 |
| 관할 조정 결정·합의 기록 | 재발 사례 참고; 적용 조건·유효기간·규정과의 정합성 확인 |

공통 메타데이터: 출처ID·문서명·원문 위치·버전·시행/종료일·관리부서·접근등급·갱신일. 조직·팀·사람·업무·시설·규정·사례를 ID로 연결한다. 인사이동 시 담당자만 교체하고 업무ID와 과거 이력은 유지한다. 개인정보는 수집·색인 전에 최소화하거나 비식별 처리한다.

## 8. 권장 아키텍처

`자료 수집·정제·권한 분류 → 구조화 지식DB + 원문/검색 인덱스 → 입력 쟁점 분석 → 규칙·키워드·벡터 검색(RAG) → 후보 점수 계산 → LLM의 근거 기반 권고·설명 → 사람 확정 → 이력DB`

- **구조화 지식DB:** 현행 조직, 사무분장, 담당자, 주관·협조 관계, 시행기간 관리.
- **RAG:** 답변 전에 관련 원문과 확정사례를 검색하고 출처ID를 전달한다. 전체 자료를 모델에 재학습시키는 방식을 전제로 하지 않는다.
- **LLM:** 비정형 입력의 쟁점 분리, 근거 해석, 추가 질문, 설명문 작성에 사용한다.
- **규칙·점수 엔진:** 소관 조건·제외 조건 적용과 재현 가능한 점수 계산을 담당한다.
- **검증·운영 계층:** 인용 존재 여부, 담당 조직 유효성, 접근권한, 출력 형식, 모델·자료 버전을 검증·기록한다.

## 9. 주관·협조 구분과 핑퐁 방지

주관부서는 핵심 행정행위와 통합 조정·회신을 맡고, 협조부서는 개별 쟁점의 검토·조치를 맡는다. 하나의 부서에 모든 실행 업무를 몰지 않는다. 독립적인 요청이 섞여 있으면 하위 과제로 분리하고 과제별 주관을 둔다. 총괄 주관이 불명확하면 조정 권한자가 정한다.

재배정 요청에는 소관이 아니라고 보는 근거, 대안 후보, 새로 확인된 사실을 기재한다. 시스템은 이전 권고·반려·확정 근거를 비교하고 동일 사건의 A→B→A 순환을 탐지한다. 예를 들어 재이송 2회 또는 순환 탐지 시 자동 이송을 멈추고 조정 담당자에게 검토를 요청하는 방식을 제안한다. 횟수와 권한은 추후 확정한다.

사건ID별로 요청·권고·확정 시각, 변경 전후 부서, 요청자·확정자, 사유·근거, 모델·데이터 버전을 보존한다. 확정된 조정 결과만 검토 후 지식베이스에 반영한다. 반복 이송이 기존 부서의 소관 점수를 자동으로 높이거나 잘못된 관행을 굳히지 않도록 한다.

## 10. 시민용 확장

일상언어 문의 → 필요한 위치·시설 정보 확인 → 담당 창구와 접수 경로 안내로 확장한다. 복합 민원은 내부에서 협업하도록 연결해 시민이 여러 부서를 직접 찾아다니는 부담을 줄인다. 외부에는 공개 가능한 조직·연락처·안내 근거만 제공하고 개인별 내부 업무분장·비공개 사례·조정 이력은 노출하지 않는다. MVP 이후 별도 단계로 추진한다.

## 11. 발표 시연 시나리오

**입력:** “아파트 앞 보도 가로수가 간판을 가리고, 낙엽 때문에 배수구도 막힙니다.”

1. 기존 상황을 짧게 제시한다: 녹지·도로·청소 업무가 섞여 관할 협의와 이송이 발생한다.
2. 시스템이 가로수 가지치기·낙엽 수거·배수시설 정비로 쟁점을 나누고 관리주체를 확인한다.
3. 가상 사무분장을 근거로 녹지 담당팀을 주관 후보, 도로·배수 담당팀을 협조 후보로 제시한다. 실제 부서명은 자료 확보 후 대체한다.
4. 예시 화면에 녹지 86점·도로 68점·청소 41점과 항목별 내역, 해당 분장 원문, 가상 유사사례 38/43건을 보여준다. 모두 시연용 수치임을 표시한다.
5. “그 나무는 공동주택 사유지 안에 있다”는 추가 사실을 입력해 기존 근거가 적용되는지 재검토하고, 관리주체 확인 필요 상태로 바뀌는 모습을 보여준다.
6. 재배정 요청과 변경 이유를 기록하고, 반복 이송 시 조정 화면으로 연결한다.

1~2분 안에 **입력 → 근거를 갖춘 권고 → 협업 분담 → 이력 확인**을 보여주는 것이 핵심이다. 실제 성능과 시연 연출은 분리해 설명한다.

## 12. MVP 범위와 검증

- 한 지자체의 경합이 잦은 3~5개 부서·팀부터 시작한다. 민원을 중심으로 만들되 제안·지시·공약·내부 업무도 입력 유형으로 구분한다.
- 현행 사무분장, 팀별 담당업무, 비식별 확정사례 약 50~100건을 수작업 검수해 준비한다. 부족하면 규정 기반으로 시작하고 사례 통계는 표시하지 않는다.
- 필수 화면: 입력·추가 질문, 주관/협조 추천과 근거·점수, 사람 확정/재배정, 사건 이력.
- 초기 제외: 전 조직 개인 담당자 실시간 연동, 실제 행정시스템 자동 이송·결재, 전면 시민 공개, 모델 재학습.
- 검증: 실제 적용 전 전문가가 합의한 별도 사례로 상위 1개·3개 후보 적합률, 주관/협조 적합성, 인용 정확성, 검토 필요 탐지, 응답시간을 평가한다. 단순·복합·소관 공백·정보 누락·조직개편 사례를 포함한다.
- 기존 수작업과 배정시간·재이송 횟수를 비교하고, 오류 유형과 부서별 편향을 점검한다. 학습·튜닝 사례와 평가사례를 분리하며 수용 기준 수치는 관계자와 정한다.

## 13. 기대 효과와 위험·운영 원칙

기대 효과는 시민의 반복 설명과 대기 감소, 직원의 관할 확인시간 절감, 간부의 조정 근거 확보, 배정의 일관성 향상이다. 반복 경합 분석은 사무분장 개선에도 활용할 수 있다. 효과는 도입 전후 최초 배정 적합률·재이송률·평균 확정시간·민원인 재접촉 횟수·직원 만족도로 확인한다. 절감률을 사전에 성과처럼 단정하지 않는다.

| 위험 | 대응 원칙 |
|---|---|
| 잘못된 인용·확신에 찬 오배정 | 실제 검색된 원문만 인용, 근거 검증, 정보 부족 시 보류·추가 질문 |
| 과거 힘의 관계·잘못된 관행 재생산 | 현행 공식 근거 우선, 확정사례 검수, 이의제기·부서별 오류 점검 |
| 조직개편·인사이동에 따른 정보 노후화 | 시행일·버전 관리, 갱신 책임자 지정, 오래된 담당자 정보 표시 제한 |
| 점수가 객관성이나 정확도로 오인됨 | 산식·결측·한계 공개, 적합도와 신뢰도 구분, 가상 수치 명시 |
| 개인정보·비공개 문서 유출 | 승인된 처리환경, 최소 수집·권한별 검색/출력·접근기록·보존기간 설정 |
| 입력·문서 속 악성 지시 | 민원·문서 내용은 분석 대상 데이터로 취급하고 시스템 지시나 권한으로 실행하지 않음 |
| 책임 회피·긴급 업무 지연 | 최종 확정자·조정 경로 명시, 긴급 사안은 기존 긴급 처리 절차 우선 |

## 14. 명칭·슬로건 후보

| 명칭 | 슬로건 |
|---|---|
| AI 업무배분기 | 애매한 업무, 근거로 길을 찾다 |
| AI 소관나침반 | 담당은 명확하게, 협업은 자연스럽게 |
| 이음행정 AI | 부서를 잇고, 민원인의 기다림을 줄이다 |
| AI 업무관할 길잡이 | 누가 맡을지, 왜 맡을지 한눈에 |

공식 설명명 후보: **근거 기반 AI 행정업무 관할·배분 지원시스템**.

## 15. 다음 단계에서 결정할 질문

1. 적용 지자체와 시범 부서는 어디이며, 가장 빈번한 경합 업무는 무엇인가?
2. 현행 사무분장과 팀·개인 업무자료를 누가 제공·검수·갱신하는가?
3. 최종 배정·조정 권한자는 누구이며 기존 이송·협의 절차와 어떻게 연결하는가?
4. 주관 지정 원칙과 문서 충돌 시 적용 기준을 조직 내에서 어떻게 합의할 것인가?
5. 과거 이력에서 최종 확정·정상 처리 사례를 구분할 수 있는가?
6. 개인정보·비공개 자료를 처리할 승인 환경과 외부 모델 사용 범위는 무엇인가?
7. 평가 정답을 누가 합의하고, 오배정 허용 수준·보류 기준·성과 목표를 어떻게 정할 것인가?
8. 발표 일정·개발 인력·예산·시스템 연동 범위는 어느 정도인가?
9. 시민용 안내는 언제 확장하며 공개 정보와 접수 책임은 어떻게 정할 것인가?

## 16. 후속 AI에 대한 작업 지침

이 문서를 기획의 출발점으로 사용하되 실제 규정·부서명·담당자·통계는 별도로 확보·검증한다. 먼저 시범 부서와 대표 경합 사례를 정하고, 데이터 스키마·화면 흐름·근거 연결 방식·평가계획을 구체화한다. **설득력을 높이기 위해 근거나 숫자를 만들어내지 않는다.** 사용자의 핵심 의도인 공정한 관할 배정, 민원 핑퐁 감소, 부서 갈등 완화를 유지한다.
