## 0. 3줄 요약

1. **무엇을 만드나:** AI 주무관들이 근무하는 **2D 가상 오산시청**입니다. 화면에서 청사 지도를 돌아다니며 방(부서)에 들어가면 AI 주무관이 인수인계, 업무 도구 제작, 다른 방과의 협업을 해 줍니다.
2. **왜 강력한가:** “담당자가 바뀌어도 업무 지식과 도구는 청사에 남는다”는 메시지에, 애매한 업무를 근거와 점수로 배정하는 **업무 핑퐁 제로(pingpong_zero)** 와 다른 팀·기존 도구를 한 곳에 모으는 **도구 플랫폼**이 더해져, 단순 챗봇이 아닌 “실제 조직 구조를 아는 시스템”이 됩니다.
3. **어떻게 보여주나:** 발표에서는 전 부서가 들어선 청사 전체를 보여주고, 시연은 불이 켜진 일부 방만 실제로 작동시킵니다. 나머지 방에는 ‘채용 예정’ 팻말을 붙입니다.

## 1. 배경: 왜 이 주제인가

### 1-1. 주제를 바꾼 이유
- 기존 주제(OSAN AI FUNDING RADAR)는 결과물이 “잘 정리된 문서”에 그쳐, 챗GPT·클로드 채팅만 잘 써도 비슷하게 나온다는 한계가 있었습니다.
- 우리가 원하는 반응은 **“와, AI가 이거까지 해?”** 입니다. 그래서 텍스트 답변이 아니라 **움직이는 화면, 즉석에서 생겨나는 도구, 부서끼리 주고받는 업무 흐름**이 보이는 주제로 바꿨습니다.

### 1-2. 주제 선정 기준 (팀 합의)
| 기준 | 이 주제에서 충족하는 방법 |
| --- | --- |
| 현실성 | 12월 초까지 클로드 코드로 만들 수 있는 범위만 실제 구현, 나머지는 비전으로 제시 |
| 놀라움 | 지도 위 봉투가 날아가고, 30초 만에 도구가 생기고, 판정이 실시간으로 바뀌는 장면 |
| 보안·내부망 | 공개 자료와 가상 사례만 사용, 발표장은 외부망 노트북 + 핫스팟 |
| 법·개인정보 | 처분 기능 없음(초안·권고만), 개인정보 입력 차단, 사진 속 얼굴·번호판 자동 가림 |
| 간부급 효능감 | 인사이동 공백, 업무 핑퐁, 부서 간 협조 지연, 전체 업무 현황 파악의 어려움을 직접 해결 |
| 시민 효능감 | 한 번에 맞는 부서 배정, 다국어 안내, 쉬운 안내문 → 시민의 반복 설명·대기 감소 |

### 1-3. 지방직 공무원의 실제 불편 (문제 정의)
1. **인사이동 = 업무 지식 증발:** 인수인계서가 형식적이고, 연간 일정·관련 법령·노하우는 전임자 머릿속에만 있습니다.
2. **업무 핑퐁:** 소관이 애매한 업무가 부서 사이를 며칠씩 떠돌고, 소관 결정이 근거보다 관행에 의존해 배정 이유가 남지 않으니 같은 갈등이 반복됩니다.
3. **도구가 흩어져 있음:** 직원들이 엑셀 계산기, 서식, AI 도구를 각자 만들어 쓰지만 공유되지 않고, 담당자가 떠나면 사라집니다. 시정연구모임 각 팀의 결과물도 발표가 끝나면 흩어지기 쉽습니다.
4. **협조 지연:** 여러 부서가 얽힌 업무는 협조 요청과 회신 취합에만 며칠이 걸립니다.
5. **간부의 시야 부족:** 어느 부서에 어떤 업무가 몰리고 어디서 핑퐁이 잦은지 한눈에 볼 수단이 없습니다.

### 4-3. 업무 핑퐁 제로(pingpong_zero) 판정 방식
이동욱 주무관이 먼저 기획한 pingpong_zero 프로젝트를 청사의 두뇌로 넣었습니다.

1. **명시 규정 우선:** 조례·시행규칙에 소관이 명시돼 있으면 그대로 따릅니다.
2. **업무적합도 점수(100점):** 코드가 계산합니다. AI(LLM)가 점수를 매기지 않습니다.
   | 항목 | 배점 |
   | --- | --- |
   | 사무분장 근거 | 40 |
   | 과거 처리 사례 | 25 |
   | 의미 유사도 | 20 |
   | 대상·행위 일치 | 10 |
   | 조직 관계 | 5 |
3. **안전장치:** 1·2위 점수 차가 10점 미만이거나 직접 근거가 없으면 ‘검토 필요’로 표시합니다. A→B→A처럼 돌거나 2회 이상 이송되면 조정 담당자에게 회부합니다.
4. **출력:** 주관 부서, 협조 부서, 항목별 점수, 인용 근거, 판정 이유를 담은 **판정서**. 배정 확정은 권한자가 합니다.
5. 가중치는 출발점이며, 경계 사례 10~20건으로 시험하면서 조정합니다.

## 5. ★ 신규: AI 도구 상가 (도구·서식 플랫폼)

### 5-1. 아이디어
오산시청에는 이미 많은 도구가 있습니다. 시정연구모임 다른 팀들이 만드는 AI 도구, 직원들이 만들어 쓰는 엑셀 계산기와 체크리스트, 부서마다 쓰는 서식들입니다. 문제는 **어디에 무엇이 있는지 모르고, 만든 사람이 떠나면 사라진다**는 점입니다.

「오산시 AI 청사」는 이 도구들이 **입주하는 플랫폼**이 됩니다. 청사 안에 ‘AI 도구 상가’를 두고, 다른 팀의 결과물과 기존 업무 도구, 서식을 가게처럼 입주시킵니다. AI 주무관은 업무를 처리하다가 필요한 도구를 상가에서 찾아 추천하거나 직접 실행합니다.

> **메시지:** “시정연구모임의 모든 결과물이 발표 후 흩어지지 않고, 오산시 AI 청사에 입주해 계속 쓰인다.”
> 우리 팀은 다른 팀과 경쟁하는 도구 하나가 아니라, **모든 팀의 성과를 담는 그릇**을 제안하는 것입니다.

### 5-2. 입주 대상
| 종류 | 예시 | 입주 방식 |
| --- | --- | --- |
| 다른 팀 AI 도구 | 시정연구모임 각 팀이 만든 웹앱·챗봇·자동화 도구 | 링크형 또는 임베드형(아래 5-3) |
| 기존 업무 도구 | 초과근무수당 계산기, 예산 집행 체크리스트, 행사 준비 목록 | 업로드형 또는 AI 주무관이 웹 도구로 다시 만들어 입주 |
| AI 주무관이 만든 도구 | ②번 기능으로 만든 도구 | 자동 입주(만든 방에 소속) |
| 서식 | 공문 서식, 신청서, 결과보고서, 회의록 양식 | 서식 보관함에 업무ID와 연결해 등록 |

### 5-3. 입주 방식 3단계
| 단계 | 방식 | 설명 | 개발 부담 |
| --- | --- | --- | --- |
| 1단계 | **링크형** | 도구 카드 + 바로가기. 청사 안에서 찾고 설명을 읽고 원래 사이트로 이동 | 매우 낮음 |
| 2단계 | **임베드형** | 청사 화면 안의 창으로 도구를 그대로 띄움 (웹 도구만) | 낮음 |
| 3단계 | **연동형** | 도구가 입력·출력 규격을 공개하면 AI 주무관이 업무 흐름 중 직접 호출하고 결과를 이어 씀 | 중간 (비전 중심) |

### 5-4. 도구 등록 카드 (모든 도구 공통)
각 도구는 아래 정보를 가진 ‘입주 카드’로 등록합니다. 이 카드가 있어야 검색·추천·상황판 통계가 가능해집니다.

| 항목 | 예시 |
| --- | --- |
| 도구 이름 | 행사 안전관리계획 점검기 |
| 만든 팀·담당자 | ○○팀 (2026 시정연구모임) |
| 한 줄 용도 | 행사 계획서를 넣으면 안전관리 누락 항목을 표시 |
| 관련 업무 | 업무ID 연결 (예: 축제·행사 운영) |
| 입력 → 출력 | 계획서 텍스트 → 누락 항목 목록 |
| 데이터 등급 | 공개자료만 / 내부자료 필요(행정망 단계) |
| 입주 방식 | 링크형 / 임베드형 / 연동형 |
| 검수 상태 | 감사실 보안 검수 완료 배지 |
| 버전·갱신일 | v1.0 · 2026-12 |

### 5-5. 청사 안에서의 쓰임
1. **찾기:** 로비 안내데스크나 상가 검색창에 “행사 안전 점검할 도구 있어요?”라고 물으면 해당 가게로 안내합니다.
2. **추천:** AI 주무관이 인수인계 체크리스트를 보여줄 때 “이 단계에는 ○○팀이 만든 △△ 도구가 있어요”라고 붙여 줍니다.
3. **서식 채우기:** 서식 보관함에서 서식을 고르면 AI 주무관이 업무 내용을 바탕으로 초안을 채워 줍니다. (최종 작성·결재는 사람)
4. **승계:** 도구와 서식은 사람이 아니라 업무ID에 붙어 있어, 담당자가 바뀌어도 방에 남습니다.
5. **통계:** 어떤 도구가 몇 번 쓰였는지, 어떤 업무에 도구가 비어 있는지가 옥상 전망대에 표시되어 다음 해 시정연구모임 주제 발굴에도 쓰입니다.

### 5-6. 안전장치
- **보안 검수:** 입주 전 감사실 체크리스트로 개인정보 입력 여부, 외부 전송 여부, API 키 노출 여부를 확인합니다. 통과한 도구에만 배지를 붙입니다.
- **책임 구분:** 각 도구의 결과 책임은 만든 팀에 있고, 청사는 찾기·연결만 담당한다고 카드에 명시합니다.
- **동의:** 다른 팀 도구는 반드시 해당 팀의 동의를 받아 입주시킵니다. 동의가 없으면 이름만 비워 둔 ‘입주 예정’ 가게로 보여줍니다.

### 5-7. 시연에서 보여줄 장면
- 상가 거리에 여러 가게가 있고, 우리 팀이 만든 도구와 (동의를 받은) 다른 팀 도구 1~2개가 실제로 열립니다.
- AI 주무관이 인수인계 중 “이 단계엔 이 도구를 쓰세요”라고 추천하고, 누르면 청사 창 안에서 바로 실행됩니다.
- 발표 멘트 예시: “오늘 발표한 다른 팀의 도구들도, 채택되면 내일부터 이 상가에 입주합니다.”

### 5-8. 확인이 필요한 점 (팀 논의)
- 다른 팀 결과물을 우리 플랫폼에 넣는 것을 심사위원·다른 팀이 어떻게 볼지. ‘흡수’가 아니라 ‘함께 쓰는 그릇’ 프레임으로 말해야 합니다.
- 다른 팀 도구가 어떤 형태(웹, 엑셀, 문서)로 나올지 아직 모릅니다. 시연 전 1~2팀에 미리 협조를 구하는 것이 좋겠습니다.
- 동의가 어렵다면 직원들이 쓰는 공개 서식과 우리 팀 도구만으로도 시연이 가능합니다.

## 6. 공통 기반: 업무 지식 베이스와 원칙

### 6-1. 업무 지식 베이스
- 조직·팀·업무·시설·규정·사례·**도구·서식**을 ID로 연결한 데이터입니다.
- 방 배치, AI 주무관의 지식, 핑퐁 판정, 연락처 안내, 도구 추천, 전망대 그래프가 모두 여기서 나옵니다.
- 인사이동 때는 담당자만 바뀌고 업무ID에 붙은 지식·이력·도구는 그대로 남습니다.

### 6-2. 자료 원칙 (시연 단계는 공개 자료만)
- 사용: 행정기구 조례·시행규칙(국가법령정보 API), 오산시 홈페이지 업무분장표·연락처, 관련 법령·공개 지침, 공개 서식.
- 비전으로만: 인수인계서, 온나라 메타데이터, 통화 기록, 실제 민원 데이터 (행정망 도입 단계).
- 개인정보가 얽힌 업무(복무·인사·복지 등)는 **공개 기준 + 가상 사례**로만 다룹니다.

### 6-3. 판단·책임·보안 원칙
| 원칙 | 내용 |
| --- | --- |
| 근거 | 검색된 원문만 인용, 없으면 “확인 필요”. ⑩ 근거 검증이 모든 출력을 다시 확인. 시연용 수치는 화면에 ‘시연용’ 표시 |
| 책임 | 처분 기능 없음. AI는 권고·초안만, 배정 확정은 권한자, 최종 판단은 담당자 |
| 보안 | 개인정보·내부문서 입력 차단, 사진 속 얼굴·번호판 가림, 민원·문서 속 지시문은 데이터로만 처리, 클로드 API 키는 서버에만 보관, 입주 도구는 보안 검수 |

## 7. 개발 범위와 일정

### 7-1. 무엇을 실제로 만드나
| 구분 | 범위 |
| --- | --- |
| 반드시 작동 | 청사 지도, ① 인수인계, ② 도구 2종, ⑤ 핑퐁 제로(경계 사례 10~20건), ⑥ 부서 안내, ⑩ 근거 검증, ★ 도구 상가(링크형·임베드형, 서식 보관함) |
| 여력 있으면 | ③ 협업 시나리오 1개, ⑦ 민원실 창구, ⑧ 사진 한 장, ⑨ 시민 검토실, ④ 능력치 카드, 다른 팀 도구 1~2개 실제 입주 |

- AI 주무관 후보 업무(내부 검토안, 제안서에는 쓰지 않음): 동 행정민원, 동 복지민원, 복무·인사·인건비, 서무회계, 홍보.

### 7-2. 기술 구성 (안)
- 화면: 웹 기반 2D 청사 지도 (브라우저에서 실행)

- 데이터: 업무 지식 베이스(JSON/DB), 법령은 국가법령정보 API
- 발표 환경: 외부망 노트북 + 핫스팟. API 사용료는 감수하는 것으로 결정

## 8. 5분 시연 시나리오

1. **0:00~0:40 로비.** “인사가 나면 업무 지식은 어디로 가고, 애매한 업무는 왜 며칠씩 떠돌까요?” 전 부서 평면도와 불 켜진 방을 보여줌
2. **0:40~1:40 업무조정실.** “가로수·낙엽·배수구” 민원 입력 → 쟁점 분리, 점수 막대, 판정서 → 봉투가 녹지·도로 방으로 날아감. “단지 안 나무”를 추가하면 판정이 바뀜 (첫 번째 “와!”)
3. **1:40~2:40 부서 방.** 봉투를 받은 AI 주무관에게 “인수인계해 주세요” → 달력·체크리스트·조문, 문앞 능력치 카드
4. **2:40~3:30 도구 제작 + 도구 상가.** “처리 일정표 도구 만들어줘” → 도구가 책상에 놓이고 바로 작동 (가장 큰 “와!”). 이어서 상가로 이동해 다른 팀 도구가 입주한 모습을 보여줌
5. **3:30~4:20 민원실 또는 현장 상황실.** 심사위원 즉석 질문 또는 사진 1건
6. **4:20~5:00 옥상 전망대.** 핑퐁 다발 구간, 업무 연결망, 도구 이용 통계 → “채택되면 불이 모두 켜지고, 모든 팀의 도구가 이 청사에 입주합니다”로 마무리
