## 1. 한 줄 정의

**오산시청을 그대로 옮긴 디지털 트윈 청사에서, AI 주무관이 인수인계를 해 주고, 애매한 업무를 근거로 배분하고, 업무 도구를 쌓아 후임자에게 물려줍니다.**

핵심 메시지: **"담당자는 바뀌어도, 업무 지식과 도구는 청사에 남는다."**

## 3. 왜 이 세 부서인가

| 부서 | 고른 이유 | 이 부서에서 보여줄 장면 |
| --- | --- | --- |
| **민원여권과** | 시민 접점이 가장 넓고, 업무 종류가 많아 인수인계 부담이 큼 | 신규 발령자가 "여권 재발급 유의사항"을 물으면 단계 체크리스트와 근거가 바로 뜸 |
| **노인장애인과** | 법령·지침이 자주 바뀌고, 동과 시 사이 업무(접수는 동, 결정은 시)가 얽혀 핑퐁이 잦음 | 시와 동 사이 애매한 업무를 단계별(접수/결정/지급)로 나눠 배분 |
| **동 행정복지센터** | 팀원 근무지(세마동·신장2동)라 실제 자료와 현장 감각이 있음. 시민이 가장 먼저 찾는 곳 | 동 창구 담당자가 "이건 동에서 받나요, 시청으로 보내나요?"를 바로 확인 |

세 부서를 고르면 **시청 본청 ↔ 동** 사이의 실제 업무 흐름이 자연스럽게 생기고, 업무배분 기능이 가장 빛나는 경계 지점이 생깁니다.

## 4. 디지털 트윈 청사

### 4-1. 원칙
- 오산시청(성호대로 141)의 건물·층·방 배치를 공개 자료에서 확인한 범위만큼 그대로 옮깁니다.
- 확인되지 않은 방은 **점선 테두리**로 그리고, 확인되면 실선으로 바꿉니다. 지어낸 배치를 실제처럼 보이지 않게 하기 위해서입니다.
- 세 부서 방만 **불이 켜지고(노란색)**, 나머지 부서는 '채용 예정' 팻말을 답니다.
- 실제 청사에 없는 **업무배분실**은 '가상 공간'으로 표시해 민원실 건물 1층에 둡니다.
- 동 행정복지센터는 청사 밖 별도 건물로, 대표 센터(세마동) 하나의 내부를 보여 줍니다.

### 4-2. 지금까지 확인된 것 (조사 결과: `docs/research_오산시청_청사배치.md`)
| 구분 | 내용 | 상태 |
| --- | --- | --- |
| 건물 | 본관, 별관(본관 동쪽, 지하1~지상5층, 2023년 개관), 민원실 건물(위층 오산버드파크), 시의회 | 확인 |
| 민원여권과 | 자치행정국 소속, 민원실 건물 1층 | 소속 확인, 층은 추정 |
| 노인장애인과 | 복지교육국 소속 | 소속 확인, 건물·층 미확인 |
| 동 행정복지센터 | 8개 동 목록과 대부분 주소·대표번호 | 대부분 확인 |
| 층별 부서 배치 | 본관 각 층 부서, 시장실·대회의실 위치 | **미확인** |

오산시 홈페이지(osan.go.kr)가 이 환경에서 접속이 막혀 층별 안내도를 직접 받지 못했습니다. **팀원이 청사 층별 안내판 사진이나 홈페이지 청사안내 화면을 찍어 주시면** 지도 편집기로 바로 옮길 수 있습니다.

### 4-3. 지도 만드는 도구
- **지도 편집기** (`/dev/map-editor`): 층별 안내도 사진을 배경으로 깔고 방을 사각형으로 그리면 JSON으로 저장됩니다. 개발자가 아니어도 쓸 수 있게 만듭니다.
- 저장된 지도는 자동 검사(방-부서 연결, 문 위치)를 통과해야 반영됩니다.

## 5. 기능 상세

### 5-1. ① AI 인수인계

**이런 사람을 위해:** 1월·7월 인사 발령으로 처음 이 업무를 맡은 주무관, 그리고 그 사람을 챙겨야 하는 팀장.

| 화면 | 하는 일 | 근거 |
| --- | --- | --- |
| 업무 카드 | 방에 들어가면 업무별 카드: 업무명, 한 줄 설명, 연간 시기, 관련 도구 수 | 자료수집양식 '업무목록' |
| 연간 달력 | "11월에 뭐 해야 해요?" → 이번 달 할 일 | '연간일정' |
| 단계 체크리스트 | 업무 하나를 고르면 처리 단계, 필요 서류, 자주 틀리는 점 + 근거 조문 | '처리단계', 국가법령정보 원문 |
| 질의응답 | 지식 베이스 안에서만 답함. 근거가 없으면 "자료에 없습니다, 전임자·팀장 확인 필요" | '자주묻는질문' |

**쌓이는 방식:** 답을 못 한 질문은 '열린 질문'으로 남고, 담당자가 답을 달아 승인하면 다음 후임자부터 바로 답합니다. 방마다 **"이 방이 배운 것 N건"** 이 보입니다.

**완료 기준:** 세 부서 각각 업무 카드 10개 이상, 근거 없는 질문에 지어내지 않고 "자료에 없음"으로 답하기.

### 5-2. ② AI 업무배분

**이런 사람을 위해:** "이거 우리 업무 아닌데요"가 오가는 업무를 받은 주무관, 그리고 조정을 맡은 팀장·과장.

**흐름:**
1. 민원·업무 문장을 넣으면 AI가 쟁점을 나눕니다.
2. 쟁점마다 후보 부서(민원여권과, 노인장애인과, 동 행정복지센터, 기타 시 부서, 외부 기관)의 **업무적합도 점수**를 **코드가** 계산합니다.
   - 사무분장 근거 40 · 과거 처리 사례 25 · 의미 유사도 20 · 대상·행위 일치 10 · 조직 관계 5
3. 시와 동이 얽힌 업무는 **단계별 주관**(접수 / 심사·결정 / 지급·통보)으로 나눠 보여 줍니다.
4. 1·2위 점수 차가 10점 미만이거나 직접 근거가 없으면 **'검토 필요'**, 같은 업무가 A→B→A로 돌거나 두 번 이상 이송되면 **조정 회부**.
5. 판정서가 나오면 봉투가 해당 부서 방으로 날아가는 애니메이션. 배정 확정은 사람이 합니다.

**쌓이는 방식:** 사람이 확정하거나 고친 판정은 '처리 사례'로 저장되어 다음 판정의 '과거 사례' 점수에 반영됩니다. 업무배분실에 **"누적 판정 N건, 사람이 고친 판정 M건"** 이 보입니다.

**시연용 경계 사례 예시** (모두 가상 문장, 정답은 팀원 확인 필요):
| 문장 | 예상 쟁점 |
| --- | --- |
| "어머니 기초연금 신청하려는데 시청으로 가요, 동으로 가요?" | 접수는 동·공단, 결정은 시 → 단계별 주관 |
| "장애인 주차표지를 새 차로 바꾸려면 어디로 가요?" | 동 접수 / 시 발급 여부 확인 |
| "여권 찾으러 동 행정복지센터에 가도 되나요?" | 민원여권과 vs 동 → 근거로 명확히 |
| "혼자 사시는 어르신 집 앞에 쓰레기가 쌓여 있어요" | 동(복지 방문) + 청소 부서 협조 |
| "장애인 보조기기 지원 신청서를 동에서 받았는데 다음은?" | 동 → 노인장애인과 송부 단계 |

**완료 기준:** 경계 사례 정답률 70% 이상, **점수 차가 큰데 틀리는 '과신 오답' 0건**.

### 5-3. ③ 업무도구 축적

**이런 사람을 위해:** 매번 엑셀로 같은 계산을 하는 주무관, 전임자가 만든 파일을 못 찾는 후임자.

| 단계 | 하는 일 |
| --- | --- |
| 만들기 | AI 주무관에게 "○○ 계산기 만들어줘" → 30초 안에 작동하는 웹 도구가 책상 선반에 놓임 |
| 안전 검사 | 외부 전송 코드, 개인정보 입력 칸이 있으면 저장 거부 |
| 고쳐 쓰기 | "칸 하나 추가해줘" → 새 버전, 이전 버전 보관 |
| 승계 | 도구는 만든 사람이 아니라 **업무**에 붙음. 인수인계 체크리스트 해당 단계에 도구가 자동으로 붙음 |
| 등록 | 직원이 쓰던 엑셀·서식, 다른 팀 AI 도구도 링크로 해당 업무 선반에 등록(만든 팀 동의 필수) |

**쌓이는 방식:** 업무마다 **"이 업무의 도구 N개"**, 자주 쓰여 검증된 도구는 '공식 선반'으로 올립니다. 시정연구모임 다른 팀의 결과물도 이 선반에 입주할 수 있습니다.

**완료 기준:** 세 부서 각 2개 이상 도구가 30초 안에 생성·실행, 인수인계 화면에서 해당 도구가 바로 열림.

### 5-4. 세 기능이 이어지는 방식

```
 동 창구에서 애매한 업무 접수
        │  ② AI 업무배분: 단계별 주관 판정 → 봉투가 노인장애인과 방으로
        ▼
 노인장애인과 방에 들어간 신규 주무관
        │  ① AI 인수인계: 이 업무의 단계 체크리스트·근거
        ▼
 체크리스트 3단계 옆에 붙은 계산 도구
        │  ③ 업무도구 축적: 전임자가 만든 도구를 그대로 사용, 고치면 새 버전
        ▼
 처리 결과가 사례로 쌓이고, 다음 판정·다음 후임자가 더 정확해짐
```

## 7. 원칙 (심사 예상 질문에 대한 답)

| 예상 질문 | 답 |
| --- | --- |
| 개인정보는? | 공개 자료와 가상 사례만 씁니다. 입력에서 주민번호·전화번호를 자동으로 가리고, 입력 원문은 저장하지 않습니다. |
| AI가 틀리면? | 점수는 코드가 계산하고 AI는 설명만 씁니다. 근거가 약하면 '검토 필요'를 띄우고, 최종 배정과 판단은 사람이 합니다. |
| AI가 법령을 지어내면? | AI는 조문 번호만 지목하고, 화면의 조문 원문은 서버가 국가법령정보에서 가져온 것만 붙입니다. 없으면 빨간색 "확인 필요". |
| 내부망에서 쓸 수 있나? | 시연은 외부망·공개 자료로 합니다. 행정망 도입 시에는 같은 구조에 내부 자료와 내부 AI를 연결하는 것을 다음 단계로 제안합니다. |
| AI가 만든 도구는 안전한가? | 외부 통신이 막힌 샌드박스에서만 실행되고, 저장 전에 금지 코드를 검사합니다. |
| 다른 부서로 늘릴 수 있나? | 부서 자료를 엑셀 양식으로 채우면 방에 불이 켜집니다. 지도와 기능은 그대로입니다. |
