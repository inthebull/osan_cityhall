# 「오산시 AI 청사」 기술 설계서 v2

> 대상: 개발자와 클로드 코드. 기획 원문은 `01_고도화기획서.md`.
> 작성: 2026-10-30 · F4O
> 범위: 기능 3개(AI 인수인계, AI 업무배분, 업무도구 축적) × 부서 3곳(민원여권과, 노인장애인과, 동 행정복지센터)

## 1. 전체 구조

```
[브라우저]
  청사 지도(SVG, 디지털 트윈) ─ 부서 방(인수인계·도구 선반) ─ 업무배분실
        │ fetch / SSE
[Next.js 서버 라우트 (Vercel)]
  /api/handover/*   AI 인수인계 (업무 카드, 달력, 체크리스트, 질의응답, 열린 질문)
  /api/dispatch/*   AI 업무배분 (쟁점 분리 → 점수 → 판정서 → 확정)
  /api/tools/*      업무도구 축적 (생성, 검사, 버전, 등록)
  /api/evidence/*   인용 대조
        │
  ├─ Claude API (키는 서버 환경변수)
  ├─ 국가법령정보 공동활용 API (조문 원문)
  └─ 지식 베이스 data/kb/*.json  ← data/intake/*.xlsx (팀 수집 자료)
```

- **배포:** GitHub → Vercel 자동 배포. 발표장은 외부망 노트북 + 핫스팟. 대비용 로컬 실행본 준비.
- **환경변수:** `ANTHROPIC_API_KEY`, `LAW_API_OC`, `DEMO_PASSCODE`, `DEMO_MODE`.
- **축적 데이터 저장:** 시연 전까지는 저장소 JSON + 개발 서버 파일 쓰기. Vercel에서는 파일 쓰기가 안 되므로 축적 기능(열린 질문, 확정 판정, 생성 도구)은 `lib/store/`를 거쳐 Vercel Postgres 또는 Supabase(무료)에 저장. 저장 계층을 처음부터 인터페이스로 나눠 둔다.

## 2. 축적 루프 (이 서비스의 핵심)

| 기능 | 쓸 때 생기는 것 | 사람이 하는 일 | 쌓이면 좋아지는 것 |
| --- | --- | --- | --- |
| AI 인수인계 | 답 못한 질문(열린 질문) | 담당자가 답을 달고 승인 | 다음 후임자가 바로 답을 받음 |
| AI 업무배분 | 판정서 | 권한자가 확정·수정 | 과거 사례 점수가 정확해지고 평가 세트가 커짐 |
| 업무도구 축적 | 생성 도구와 새 버전 | 쓸 만한 도구를 '공식 선반'으로 올림 | 업무마다 검증된 도구가 남아 후임자에게 승계 |

화면 곳곳에 "이 방이 배운 것 N건", "누적 판정 N건", "이 업무의 도구 N개" 카운터를 둬서 축적이 눈에 보이게 한다.

## 3. 기술 선택

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 프레임워크 | Next.js App Router + TypeScript + Tailwind | 화면과 서버 API 한 저장소, Vercel 무료 배포 |
| 지도 | SVG + Framer Motion | 평면도 표현과 클릭·애니메이션이 쉽고 디버깅 용이 |
| 상태 | zustand | 아바타 위치, 열린 방, 봉투 큐 |
| 검색 | BM25 + LLM 키워드 추출 | 임베딩 서버 없이 시작 |
| AI | Claude API, 서버 라우트 | 키 보호, 모델명은 `lib/ai/models.ts` 한 곳 |
| 저장 | JSON(초기) → Postgres(축적) | `lib/store` 인터페이스로 교체 가능 |
| 엑셀 변환 | SheetJS(`xlsx`) | 팀 수집 양식 → JSON |
| 테스트 | Vitest, Playwright | 점수·검사 단위 테스트, 시연 E2E |

## 5. 데이터 모델 (`data/schema/`)

```
Building 1─N Floor 1─N Room ──(dept_id)── Dept 1─N Team 1─N Task
Task N─N Rule      Task 1─N Step      Task 1─N FAQ      Task 1─N Schedule
Task 1─N Case      Task 1─N Tool(versions)              OpenQuestion → FAQ
Verdict → Case(kind: decided)
```

| 파일 | 핵심 필드 |
| --- | --- |
| `orgs.json` | dept_id(D-CIVIL, D-ELDER, D-DONG-<동>), name, floor_room_id, phone, teams[] |
| `tasks.json` | task_id, dept_id, title, text(사무분장 원문), targets, actions, places, rule_ids, schedule[{month, todo}], steps[{order, name, docs, cautions, rule_id}], competency, source |
| `rules.json` | rule_id, law_name, article, text, fetched_at |
| `faqs.json` | faq_id, task_id, q, a, approved_by_role, approved_at |
| `open_questions.json` | oq_id, task_id, q, asked_at, status(open/answered) |
| `cases.json` | case_id, kind(virtual/public/decided), summary, stage_leads{접수, 결정, 지급}, cooperate[], edited_by_human |
| `tools.json` | tool_id, task_ids, name, mode(generated/link/embed), versions[{v, html_ref, diff_summary, created_at}], official(bool), uses, consent, review |
| `officers.json` | officer_id, dept_id, display_name, tone |

엑셀 양식 시트 → JSON 대응: 업무목록→tasks, 연간일정→tasks.schedule, 처리단계→tasks.steps, 자주묻는질문→faqs, 도구·서식→tools(link), 경계사례→data/cases/boundary.json.

## 6. AI 업무배분 알고리즘

```
input → split(LLM) → issues[]
for issue:
    f = features(LLM)                     # 대상, 행위, 장소, 단계 단서(신청/발급/지급…)
    if explicit_rule(f): decide by rule
    C = {민원여권과, 노인장애인과, 동 센터, 기타 시 부서, 외부 기관}
    score(c) = 40·duty + 25·case + 20·semantic + 10·target_action + 5·org   # 코드, 결정적
    stage split: 접수/심사·결정/지급 단계별로 최고점 부서
    if top1 - top2 < 10 or no direct evidence → needs_review
history: A→B→A or transfers ≥ 2 → escalate
report(LLM): 설명문만, 부서·점수 변경 불가(코드로 일치 검사)
확정 → cases.json(kind: decided)
```

## 7. AI 호출

| 용도 | 출력 형식 | 비고 |
| --- | --- | --- |
| 인수인계 질의응답 | `{answer, used_task_ids[], rule_ids[], found: bool}` | found=false면 열린 질문으로 저장 |
| 달력·체크리스트 | 지식 베이스 그대로 렌더링, AI는 요약 문장만 | 빈 칸은 "자료 필요" |
| 쟁점 분리·특징 추출 | JSON 스키마 강제, temperature 0, 입력 해시 캐시 | 빠른 모델 |
| 판정서 설명 | 문단 | 부서·점수 일치 검사 |
| 도구 생성 | `{html, card}` | 가장 강한 모델, 정적 검사 후 저장 |
| 도구 수정 | `{html, diff_summary}` | 새 버전 |

공통: 사용자 입력은 `<user_data>`, 지식 베이스 발췌는 `<kb>`. 인용은 rule_id로만 받고 원문은 서버가 붙임.

## 8. 보안·개인정보
- 입력 전 개인정보 패턴(주민번호, 휴대전화, 이메일, 상세 주소) 감지 → 가림 후 전송
- 생성 도구: `sandbox="allow-scripts"`, CSP `connect-src 'none'`, 금지 패턴 정적 검사
- 입력 원문 로그 저장 안 함(해시 + 결과만)
- 발표 외 접근은 `DEMO_PASSCODE`
