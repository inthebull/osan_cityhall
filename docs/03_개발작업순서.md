## 1단계 (11/6~11/12): 청사 지도와 빈 방
**1-1. 디지털 트윈 지도** (`map-builder`)
> "data/research/osan_cityhall_layout.json과 docs/research_오산시청_청사배치.md를 읽고 본관 층별 JSON을 만들어. 민원여권과·노인장애인과 방은 active, 나머지는 planned. 동 행정복지센터는 /dong 화면에 오산시 지도와 대표 센터 1곳으로."
- 완료: 실제 배치대로 층 전환, 세 부서 방 클릭 이동, 아바타 길 안내

**1-2. 지도 편집기** (`map-builder`)
> "/dev/map-editor를 만들어. 층별 안내도 사진을 깔고 방을 그려 JSON으로 저장."
- 완료: 실물 안내도로 한 층을 다시 그려 저장

**1-3. 자료 가져오기** (`kb-curator`)
> "scripts/import-intake.ts로 data/intake 엑셀을 data/kb JSON으로 바꿔. 오류는 엑셀 시트·행 번호로 알려 줘."
- 완료: 예시 행만 있는 양식으로도 변환·검사 통과

## 2단계 (11/13~11/19): AI 인수인계 ① (`ai-officer`)
> "세 부서 방에 업무 카드, 연간 달력, 단계 체크리스트를 지식 베이스 그대로 보여 줘. 빈 칸은 '자료 필요'. 그다음 지식 베이스 안에서만 답하는 질의응답과 열린 질문 저장."
- 완료: 근거 없는 질문에 "자료에 없음" + 열린 질문 저장 테스트 통과
- 축적: 열린 질문에 답을 달아 승인하면 FAQ로 추가 → "이 방이 배운 것 N건"

## 3단계 (11/20~11/26): AI 업무배분 ② (`pingpong-engine`)
> "lib/pingpong 파이프라인을 설계서 6장대로 구현. 후보는 세 부서 + 기타 시 부서 + 외부 기관, 단계별 주관(접수/결정/지급) 지원. score.ts는 순수 함수 단위 테스트. 업무배분실 화면에 점수 막대와 판정서, 확정 시 봉투가 방으로 날아가는 애니메이션."
- 완료: 경계 사례 정답률 70% 이상, 과신 오답 0건
- 축적: 확정 판정 → 사례로 저장 → 과거 사례 점수 반영 → "누적 판정 N건"

## 4단계 (11/27~12/3): 업무도구 축적 ③ (`tool-library`)
> "방 화면 책상에 도구 선반. '○○ 만들어줘'로 단일 HTML 도구 생성 → 정적 검사 → 샌드박스 실행 → 업무ID에 저장. 수정하면 새 버전. 인수인계 체크리스트 단계에 맞는 도구 자동 표시. 다른 팀 도구는 링크·임베드로 등록."
- 완료: 세 부서 각 2개 이상 도구 30초 안에 생성, 금지 패턴 테스트 통과
- 축적: "이 업무의 도구 N개", 공식 선반 승격
